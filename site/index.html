Protocol specification · Draft 1.0

A protocol for direct LED control

Opalinx is an acknowledged binary protocol between host software and addressable LED controllers. It carries pixel data, device queries, configuration, and explicit display commits over a reliable byte stream such as USB or serial.

Read the specification

Where it fits

These protocols solve related but different problems. Opalinx is intended for a direct, point-to-point controller link where the host needs acknowledgement and device state; it does not replace stage-lighting or network-distribution protocols.

Open Pixel ControlTCPTransport-level deliverySimple pixel streaming in OPC-compatible systems

Opalinx does not make the LEDs themselves refresh faster. Its distinction is a closed control loop: framing is checked, operations return typed results, and each displayed frame can be confirmed.

Protocol scope

The core specifies framing, device information, configuration, pixel transfer, coordinated output, and recovery without prescribing a software or firmware architecture.

01

Framing and validation

COBS framing, CRC protection, defined errors, and transaction correlation over reliable byte streams.

02

LED data and output

RGB and RGBW pixel data, channel configuration, and coordinated multi-channel Show operations.

03

Extension points

Information records and namespaced vendor messages allow additive extensions to the core protocol.

Client libraries

Client implementations are documented separately from the protocol. They share the same wire semantics and conformance corpus.
